# 한국 사업 아이디어 검증 도구 v0.1 개발 계획

2026-10-08 기준. 예비·초기 창업자가 한국 시장의 고객 모수, 비교기업, 손익 구조를 검토하고 다음 검증 실험을 정하는 로컬 Skills + MCP 패키지를 만든다. KOSIS·OpenDART 실호출 검사 9개가 통과했으므로 아래 최소 범위의 구현은 착수할 수 있다. 통계로 관측되는 모수와 구매 의향·전환율 같은 사업 가정을 구분하는 것이 핵심이다.

## 확정 사항과 이번 계획의 전제

| 구분 | 내용 |
|---|---|
| 사용자가 확정 | 사업 아이디어 검증 중심, 로컬 패키지만 제공, 사용자가 자기 API 키 입력 |
| 사용자가 선택한 예제 | 서울 소형 학원 예약·결제 SaaS, 서울 1인가구 냉동식 구독, 마포구 방문청소 |
| 구성안 | 독립 실행 가능한 스킬 3개와 공유 stdio MCP 서버 1개 |
| 조회 범위 제안 | KOSIS 전체 검색은 제공하고 수치 조회는 검증된 표 3개와 검증된 코드 조합부터 지원 |
| 범위 선택 대기 | 사용자에게 범용 조회와 검증된 표 우선 중 선택을 요청했다. 이 계획은 후자를 전제로 한다. 무응답을 확정으로 간주하지 않는다. |
| 구현 기본값 제안 | Python 3.10 이상, 공식 MCP Python SDK, Decimal 계산, 직접 작성한 코드·문서 MIT 라이선스 |

MCP는 근거 데이터를 반환하고, 스킬은 이를 사업 질문에 연결한다. KOSIS·DART가 포괄하지 않는 소상공인 경쟁사, 실제 제품 가격, 고객 지불 의향은 별도 공개 웹 자료·사용자 자료·인터뷰로 확인한다. 공개 웹 도구는 선택 사항이다.

각 스킬은 MCP가 없거나 키가 없을 때도 사용자 자료·공개 원문을 사용해 진행할 수 있다. 실제 API 조회가 없으면 관측값을 채우지 않는다. 종합 스킬은 나머지 스킬의 존재를 가정하기보다 필요한 조사 절차와 MCP 도구명을 자체 참조 문서에 포함한다.

종합 결과는 사업 정의, 근거가 있는 시장 모수, 경쟁·대체재, 손익 및 처리능력, 자료 공백, 검증 실험 순서로 작성한다. 성공 확률을 점수로 꾸미지 않고 `실험 진행`, `조건 수정 후 재검토`, `핵심 자료 확보 전 보류`를 근거와 함께 제안한다.

## KOSIS 지원 레지스트리

검색에서 찾은 표와 조회를 지원하는 표를 구분한다. 검색 결과에 `query_supported`를 표시하고, 미지원 표는 공식 링크와 필요한 검증 항목을 반환한다. 지원되는 표라도 레지스트리에 없는 분류 코드는 API 호출 전에 거절한다.

| 표 ID와 관측 범위 | 분류와 최초 지원 코드 | 조회 항목 | 실호출 결과 |
|---|---|---|---|
| `101 / DT_1PL1502` 성 및 연령별 1인가구 시군구 | 지역 A=`11` 서울특별시, 연령 B=`000` 합계. 분류 2개 | `T00` 1인가구 | 2025년 1,699,910가구 |
| `101 / DT_1K52D01` 시도·산업·사업체구분별 사업체수 | 지역 SGG_201804=`11` 서울, 산업 B=`P` 교육 서비스업(85), 사업체구분 C=`0` 계. 분류 3개 | `T1` 사업체수 | 2023년 49,232개 |
| `101 / DT_1K52D03` 시도·산업·종사자규모별 사업체수 | 지역 SGG_201804=`11` 서울, 산업 B=`P` 교육 서비스업(85), 종사자규모 E=`1` 1~4명. 분류 3개 | `T1` 사업체수 | 2023년 39,307개 |

이는 최소 지원 조합이다. `describe_table`은 표 전체 분류를 모두 열거했다고 주장하지 않고 `supported_members`와 `coverage=verified_subset`을 반환한다. 전국·연령·성별·다른 산업·종사자수 등의 확장은 공식 코드와 실호출을 함께 검증한 뒤 레지스트리에 추가한다. [1인가구 표 구조](https://kosis.kr/statHtml/statHtmlContent.do?orgId=101&tblId=DT_1PL1502&language=ko&dbUser=NSI.), [사업체구분 표 구조](https://kosis.kr/statHtml/statHtmlContent.do?orgId=101&tblId=DT_1K52D01&language=ko&dbUser=NSI.), [종사자규모 표 구조](https://kosis.kr/statHtml/statHtmlContent.do?orgId=101&tblId=DT_1K52D03&language=ko&dbUser=NSI.)

1인가구 표에 세 번째 분류 `objL3`를 넣지 않는다. 성별은 분류가 아니라 조회 항목에 해당한다. `getMeta&type=ITM`은 알고 있는 분류값의 설명 조회에 활용하며 임의 표 전체 구조를 자동 발견하는 기능으로 취급하지 않는다. 공개 UI의 하위 분류 호출은 접근 차단 응답을 반환했으므로 운영 MCP가 이에 의존하지 않게 한다. [공식 분류값 설명 가이드](https://kosis.kr/openapi/devGuide/devGuide_060104List.do)

`format=json`과 `jsonVD=Y`를 함께 사용한다. 연간 자료 요청 코드 `Y`와 응답의 `PRD_SE=A`는 서로 다르므로 요청 주기·응답 원문 주기를 모두 저장한다. 값 문자열 `DT`, 단위, 기준시점 `PRD_DE`, 수정일 `LST_CHN_DE`, 분류명·코드를 보존한다. 수정일을 기준연도로 표시하지 않는다. [공식 자료 조회 가이드](https://kosis.kr/openapi/devGuide/devGuide_0201List.do)

2023년 교육서비스업 사업체 수는 2026년 현재 학원 수가 아니다. 기준연도와 조회일을 함께 보여 주고 자료의 시차와 넓은 업종 범위를 명시한다. 두 사업체 표는 시도 단위여서 마포구·동 단위 값을 제공할 수 없다.

### 표와 코드 확장 절차

1. 공식 표명·기관·차원 순서·분류 코드·항목·단위·주기를 확인한다.
2. 작은 조합으로 실제 조회해 코드와 반환 이름·단위·기준시점을 대조한다.
3. 지역·산업의 최소 공개 단위와 개편된 산업분류 적용 시점을 기록한다.
4. 레지스트리에 `verified_at`, 출처, 지원 코드와 제한을 추가하고 회귀 검사에 반영한다.
5. 단위·분류의 변경을 감지하면 해당 조합을 미지원으로 처리한다. 임의 코드로 대체하지 않는다.

현재 마포구 코드, 학원 상세 업종 코드, 가계지출 표, 임금 표는 확장 대상이다. 마포구·학원 상세 분석은 자료 공백을 드러내는 예제로 제공하고, 이 코드 확보를 전체 MVP 착수의 선행 조건으로 두지 않는다.

## MCP 도구 계약

도구 6개를 읽기 전용으로 제공한다. API 키를 도구 인자로 받지 않는다. 아래 한도는 v0.1의 제품 제한이며 제공기관의 공식 최대치와 구분한다.

| 도구 | 입력 | 성공 출력과 제한 |
|---|---|---|
| `kosis_search_tables` | `keyword`, 선택 `org_id`, `page=1`, `page_size=10` | 기관·표 ID/명, 수록기간, 공식 링크, `query_supported`. 페이지 크기 1~20. 공식 `startCount=page`, `resultCount=page_size`로 전달하며 페이지1·2 차이 검사 필수 |
| `kosis_describe_table` | `org_id`, `table_id` | 지원표: 차원 순서·필수 차원·검증 코드·항목·주기·제한·출처. 미지원표: `unsupported`, 필요한 확인 항목·공식 링크. 범용 자동 스키마 탐색을 약속하지 않음 |
| `kosis_query_statistics` | `org_id`, `table_id`, `dimensions`, `item_ids`, 선택 `year` | `dimensions`는 `region`, `age`, `industry`, `business_type`, `employee_size` 중 해당 표의 차원만 사용. 값은 describe가 반환한 코드 목록. `year` 생략 시 최신 1시점, 지정 시 해당 연도. 연간만 지원, 조합별 검증기간 안에서 호출. 예상 셀 수 최대 1,000, `ALL` 금지 |
| `dart_find_company` | `name`, `match_mode=exact`, `limit=10`, `refresh=false` | 회사명·8자리 `corp_code`·상장사6자리 `stock_code`·수정일. 비상장사의 빈 종목코드는 원문을 보존하고 정규값은 null. exact/prefix 검색, 결과 최대20. 동명 후보는 `ambiguous`, 사용자가 선택하도록 반환. ZIP/XML 고유번호 색인을 로컬 저장 |
| `dart_list_disclosures` | `corp_code`, `start_date`, `end_date`, 선택 `disclosure_type`, `latest_only=true`, `page=1`, `page_size=10` | 접수번호·공시명·접수일·정정 표시·공식 링크·총건수/다음 페이지. 회사번호 필수, YYYYMMDD 날짜 검증, 페이지 크기1~100 |
| `dart_get_financials` | `corp_code`, `business_year`, `report_code`, `fs_div`, `offset=0`, `limit=200` | 계정ID/명, 표 구분, 당기·누적·전기 금액, 기간명, 통화, 접수번호·원문 링크. limit1~500, 총계정 수·다음 offset 반환. 전체를 제공한 것처럼 잘라내지 않음 |

`corp_code`는 8자리 문자열이다. `report_code`는 연간 `11011`, 반기 `11012`, 1분기 `11013`, 3분기 `11014`. `fs_div`는 `CFS` 또는 `OFS` 필수이며 자동 대체하지 않는다. 회사번호 색인에 있는 기업도 재무 API 대상이 아닐 수 있다. [공식 회사번호 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), [공시검색 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [전체 재무제표 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)

KOSIS 검색의 `startCount`는 페이지 번호다. 공식 예시에서 `resultCount=20`, `startCount=2`는 21~40번째 결과를 뜻하므로 행 시작 위치로 계산해 보내지 않는다. [공식 통합검색 가이드](https://kosis.kr/openapi/devGuide/devGuide_0701List.do)

최초 호출 예시는 다음과 같다.

```json
{
  "org_id": "101",
  "table_id": "DT_1PL1502",
  "dimensions": {"region": ["11"], "age": ["000"]},
  "item_ids": ["T00"]
}
```

### 공통 결과와 오류 처리

모든 도구는 구조화된 결과와 읽을 수 있는 텍스트를 함께 제공한다. 공통 필드는 `status`, `data`, `provenance`, `warnings`, `pagination`이다. `status`는 `ok / no_data / ambiguous / unsupported / error`이며 `data`의 타입은 도구별로 고정한다.

- `ok`: 자료 반환. 결측 셀은 값 상태를 별도로 표시한다.
- `no_data`: 유효한 조건이지만 자료 없음. DART `013`도 이 상태이며 숫자0과 다르다.
- `ambiguous`: 회사 동명 후보 존재. 후보를 자동 결정하지 않는다.
- `unsupported`: 표·코드·주기 또는 비교기준이 현재 지원 범위 밖이다.
- `error`: 잘못된 입력·키 누락·키 거절·호출 제한·네트워크·응답 구조 변경. 고정 오류코드와 해결 힌트만 반환하고 MCP `isError=true`를 사용한다.

`provenance`에는 제공기관, 키 없는 공식 링크, 조회시각 UTC, 적용한 필터가 들어간다. 통계에는 관측기간·수정일·원문 단위·요청 및 응답 주기를, 재무에는 회사번호·사업연도·보고서·CFS/OFS·접수번호·당기/누적 기간명을 포함한다.

수치는 `raw_value`와 정규화된 유한 Decimal 문자열 `numeric_value`로 반환한다. 정상 음수·양수의 부호는 보존한다. `value_state`는 `numeric / empty / non_numeric`이며 공백·비숫자 기호는 `numeric_value=null`로 반환한다. 비숫자 기호의 의미는 표별 공식 주석으로 검증한 경우에만 `symbol_meaning`에 표시하고 미확인 부호를 0이나 확정된 결측 사유로 바꾸지 않는다. API JSON의 금액에 웹 화면의 백만원 단위를 임의로 곱하지 않는다. 서로 다른 단위·통화·기간을 합산하지 않는다.

재무의 `thstrm_amount`와 `thstrm_add_amount`는 별개 필드로 보존한다. 분·반기 손익의 기간값과 누적값을 섞지 않고 원문 기간명·보고서 코드까지 보여 준다. 계정명만으로 매출·영업이익을 확정하거나 현금흐름표·손익계산서의 유사 계정을 합치지 않는다. 자동 핵심계정 매핑은 v0.1 범위에서 제외하고 비교에 사용할 계정과 기간을 명시적으로 선택한다. [공식 재무 필드 설명](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)

## 사업 판단과 손익 계산 기준

입력을 `observed` 공식/공개 관측값, `user_provided` 사용자 자료, `proxy` 대리지표, `assumption` 가정, `derived` 계산값으로 구분한다. 각 항목에 기간·단위·출처 또는 가정 작성자·사용 이유를 붙인다. 데이터 신뢰성과 사업의 성공 가능성을 하나의 점수로 합치지 않는다.

시장 모수는 가구·사업체 등 해당 통계 단위로 먼저 제시한다. 주소 가능한 고객 수, 도달률, 구매율, 가격을 넣은 TAM/SAM/SOM은 그 입력이 적절할 때만 별도 시나리오로 계산한다. 교육서비스업 전체 사업체에 학원 SaaS 요금을 곱해 학원 시장 실측 매출이라고 하지 않는다. 개인 대상 서비스에 가구 수를 인원 수로 바꾸지 않는다.

손익은 다음 기준을 고정한다.

```text
단위 기여이익 = 단위 순매출 − 단위 변동비
월 손익분기 수량 = ceil(월 고정비 / 양의 단위 기여이익)
월 영업손익 시나리오 = 월 수량 × 단위 기여이익 − 월 고정비
서비스 최대 월 수량 = floor(월 가용시간 / 건당 작업·이동·대기시간)
```

- 부가세 제외 기준을 기본으로 하고 사용자 매출·비용의 부가세 포함 여부를 확인한다. 세율·세무처리는 사용자 입력이며 법정 세무 계산기를 제공하지 않는다.
- 기여이익이 0 이하이면 유한한 손익분기점이 없다고 표시한다.
- 구독은 고객/월, 방문청소는 건, SaaS는 유료 사업체/월로 통일한다. 건수 손익분기점과 고객 수를 혼동하지 않는다.
- 광고비·CAC·지원비·결제수수료·환불·폐기·사업주 노동비를 필요한 항목에 한 번씩 배치한다. 고정비와 변동비에서 같은 비용을 중복 계산하지 않는다.
- 작업시간뿐 아니라 이동·대기시간을 포함한다. 손익분기 수량이 처리능력을 넘으면 현재 조건으로 운영 불가능하다고 표시한다.
- 초기 현금·개업 비용·월별 판매량·현금 수금/지급 가정이 없으면 12개월 현금흐름과 생존기간을 만들지 않는다. 월 영업손익을 현금잔액으로 표시하지 않는다.

결정적인 가정이 빠지면 최소 질문으로 확인한다. 데모에는 합성 가정을 사용하되 모든 금액·수요·전환율을 가정이라고 표시한다. 계산은 세 예제가 함께 사용하는 `economics.py`와 로컬 JSON 입력 계산 스크립트로 실행해 모델의 암산에 맡기지 않는다. MCP 도구 수는 6개를 유지한다.

HTTP 구현은 SDK 의존성과 맞는 `httpx2`를 직접 의존성으로 선언하고 호환 버전을 lock한다. 과거 v1의 `FastMCP` 예제를 섞지 않는다. [공식 v2.3.0 README](https://github.com/modelcontextprotocol/python-sdk/blob/v2.3.0/README.md), [정식 패키지 정보](https://pypi.org/project/mcp/2.3.0/), [공식 의존성 선언](https://github.com/modelcontextprotocol/python-sdk/blob/v2.3.0/pyproject.toml)

### 로컬 실행과 인증정보

공개 패키지에는 키가 비어 있는 `.env.example`을 제공한다. MCP는 환경변수 `KOSIS_API_KEY`, `DART_API_KEY`를 읽는다. 실행 호스트 설정의 env 또는 명시적 `--env-file` 옵션으로 전달하고, 키 누락 때문에 전체 서버가 종료되지는 않게 한다. 해당 제공기관 도구만 고정 `missing_api_key` 오류를 반환한다.

stdio stdout에는 MCP 메시지만 쓰고 로그는 stderr에 쓴다. GET URL·헤더·응답 원문·원문 예외 문자열을 로그에 남기지 않는다. 사용자·키마다 쿼터가 달라 호출 제한은 고정 오류코드로 반환하며 무한 재시도를 하지 않는다. HTTP 타임아웃15초, 자동 재시도 없음으로 시작한다.

회사번호 색인은 플랫폼별 사용자 캐시 디렉터리에 원자적으로 저장한다. 24시간 갱신 정책과 명시적 `refresh`를 제안한다. 갱신 실패 시 기존 색인을 사용했다는 경고와 색인 시각을 함께 반환한다. 공시·재무·통계 수치는 초기에는 영구 캐시하지 않아 정정된 자료가 조용히 남는 문제를 줄인다. 캐시가 없으면 네트워크 오류를 반환한다.

본인이 발급받은 키를 사용하는 로컬 구성이며 운영자 공용 키를 배포하지 않는다. API 호출 자체는 제공기관으로 전달된다. 코드의 MIT 라이선스와 통계·공시 데이터 이용조건은 별개이며 보고서에 출처를 표시한다. 다른 저장소의 스킬을 복사할 때에는 각 파일의 라이선스를 확인하고 고지를 유지한다. 검증하지 않은 스킬 모음 전체를 복제하지 않는다. [KOSIS 이용약관](https://kosis.kr/openapi/introduce/introduce_02List.do), [OpenDART 이용약관](https://opendart.fss.or.kr/intro/terms.do)

## 남은 범위 선택과 후속 확장

구현 전 사용자 선택이 필요한 사항은 KOSIS 수치 조회 범위다. 검증된 표 우선이면 이 계획대로 진행하고, 임의 표 범용 조회를 선택하면 전체 분류 탐색·코드 수집·대용량 제한·표별 예외 처리를 별도 선행 작업으로 추가한다. 현재 getMeta와 공개 UI만으로 범용 발견을 보장할 수 없다.

정확한 학원·마포구 분류, 지출·임금 통계, 실제 경쟁 제품 자료, 사업부문 공시 본문 추출, 세무/인허가 자료, 원격 서버는 후속 확장 후보다. 이 가운데 필요한 자료는 현재 결과에서 공백으로 표시한다. 통계 모수와 손익 계산을 검증하는 v0.1에 모두 구현할 필요는 없다.

직접 작성한 코드·스킬의 MIT 공개를 기본안으로 둔다. 최종 공개 저장소 이름·라이선스 선택·GitHub 게시 등 외부 상태 변경은 로컬 결과가 검증된 뒤 결정한다.

API는 HTTP 상태와 응답의 성공 상태를 함께 검사한다. 실제 금액 문자열과 누적 필드가 숫자로 해석 가능함을 검사했으며 이 결과가 분·반기 비교 알고리즘까지 검증했다는 뜻은 아니다. 보고서 기간을 구분해 계산하는 회귀 검사는 본체 구현 단계에서 수행한다.
